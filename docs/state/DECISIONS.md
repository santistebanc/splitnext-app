# Decisions

| Id | Decision | Made in | Why |
| --- | --- | --- | --- |
| D-001 | Use remote Supabase project `splitnext-v3` (`ycpkguwfxlhpovnsuujr`, eu-central-1); do not reuse legacy `splitnext` | bootstrap | Fresh empty project matching locked architecture; old project has incompatible schema/functions |
| D-002 | Store access tokens (and device_user_id) in `expo-secure-store` | bootstrap | Long-lived capability secrets; OS keychain/keystore over plain KV |
| D-003 | Dev/demo on physical phone via Expo Go | bootstrap | Real mobile path from WSL; web SQLite is alpha; Expo Go cannot do HTTPS app links (invites later need a dev build) |
| D-004 | Separate `create-group` Edge Function mints first access token; `merge`/`fetch`/`rt-jwt` require it | slice 0001 | Create cannot call merge before a token exists |
| D-005 | Expo app at repo root; `supabase/` alongside | slice 0001 | No monorepo until a second package appears |
| D-006 | `rt-jwt` falls back to `auth_mode: anon_channel` when no mintable JWT secret is configured | slice 0001 | New Supabase projects use ES256 signing keys; legacy JWT secret is not injected into Edge Functions. Capability check still gates subscription; private minted JWT when `JWT_SECRET`/`SUPABASE_JWT_SECRET` is set |
| D-007 | Fetch Edge Function slug is `fetch-entity` (not `fetch`) | slice 0001 | Slug `fetch` produced intermittent HTML/502 responses that broke client JSON parsing |
| D-008 | Create path inserts group via `create-group`; merge→wake→fetch proven via hub bump | slice 0001 | Post-create merge at v1 would be rejected (`version_not_greater`); bump exercises the sync loop |
| D-009 | On group open and app foreground: flush queue + one group fetch (thin missed-wake catch-up) | slice 0002 | Offline bumps must upload without another tap; full missed-wake protocol stays parked |
| D-010 | Foreground sync covers all lobby group ids, not only the open group | slice 0002 | Offline edits on any known group should upload without opening that hub |
| D-011 | Create group stays empty; creator binds via Add member → This is me | slice 0003 | Matches empty-create direction; no auto-member |
| D-012 | On open/foreground, list members + binds for the group (apply by version) | slice 0003 | Thin roster catch-up without full missed-wake protocol |
| D-013 | Slice 0003 hub UI is list + add + This is me + You (Name); rename/leave/rebind parked | slice 0003 | Prove membership spine before chrome |
| D-014 | At most one active bind per device_user_id per group; same member on multiple devices allowed | slice 0003 | Assumed member is per-install; claimed-slot policy stays with invites |
| D-015 | Bind.member_id must reference a member in the same group (composite FK + merge check) | slice 0003 | Prevent cross-group bind via crafted merge |
| D-016 | Outbound queue identity is `entity_type + id + version`; `merge` returns all three per result | slice 0004 | Dropping by bare `id` discarded a pending newer version of the same entity |
| D-017 | `lastError` is a typed `SyncError` `{ code, message, at }`, cleared on every success; old string values are coerced on read | slice 0004 | String prefixes could not be matched on, and stuck red after a good sync |
| D-018 | Flow tests run the real client against a fake `src/api/edge.ts`, importing the server's own `shouldAccept` | slice 0004 | One wire boundary makes flows testable in process; sharing the rule stops the fake from disagreeing with the server |
| D-019 | Flow tests gate the demo gate and slice close, not every commit | slice 0004 | Commits inside a slice are work-in-progress; a per-commit gate gets bypassed rather than obeyed |
| D-020 | Binding stays open until the group's first live expense, then closes for good | slice 0005 | Before there is money in the group a wrong tap costs nothing, so every member stays offerable and the claim can be moved; afterwards expenses are attributed to the payer and moving a bind would silently re-attribute them. |
| D-021 | One bind per device per group: re-binding re-points the existing bind, never adds a second | slice 0005 | Two live binds would make "which member am I?" depend on iteration order. |
| D-022 | Web uses `localStorage` for both secrets and durability, not the wasm sqlite path | slice 0006 | expo-sqlite on web needs `createSyncAccessHandle`, which headless Chromium does not implement — and headless is the environment the web target exists to serve. |
| D-023 | Platform splits use `.web.ts` file resolution, never a `Platform.OS` branch in a caller | slice 0006 | Metro picks the file, so the native module never enters the web bundle and callers stay ignorant of platform. |
| D-024 | Allocations ride inside the expense entity as jsonb, not as child rows | slice 0007 | One version number covers the whole split, so merge cannot accept a new amount while rejecting one of its shares — the entity-level protocol has no transaction to do it with. |
| D-025 | Expenses split equally across the members live at record time, remainder cents handed out in sorted member-id order, frozen into the expense | slice 0007 | Two devices with the same roster in different insertion orders must produce identical allocations or merge flaps; freezing means a member added later joins the next expense, not this one. |
| D-026 | Balances are derived on read from live members + live expenses, never stored | slice 0007 | Nothing to keep in sync and nothing to migrate; the fold is pure and testable. |
| D-027 | Persisted timestamps are repaired at store open, not by changing the persisted format | slice 0007 | Legend revives ISO strings into `Date` before any reviver hook sees them; a format change would leave every already-persisted store broken. |
| D-028 | A slice is a branch → PR gated on tests + typecheck → squash merge → tag `slice-NNNN` on `main` | slice 0008 | The repo now has a remote and CI, so the gate can be enforced rather than remembered; `main` still reads one line per slice. |
| D-029 | The process is vendored into the repo at `.claude/skills/`, with `AGENTS.md` as the entry point | slice 0008 | A clone should carry the loop; depending on a machine-local skill install makes the repo unusable to any other agent. |
| D-030 | The published board is regenerated by CI from `docs/state/`, never served from the committed `docs/slicer.html` | slice 0008 | A stale commit of a generated file can then never become the published truth. |
| D-031 | The web app deploys to the same GitHub Pages site under `/app`, not to a separate host | slice 0008 | No second account and no deploy token beyond the `EXPO_PUBLIC_` values the client ships anyway; the board's "Open the app" link stays same-origin. The trade is no per-PR preview URL — a Vercel or Cloudflare project can be added if that ever earns its keep. |
| D-032 | Board path chips point at GitHub `blob/main`, and only a board served from localhost opens the editor | slice 0008 | The published board has readers with no clone; the editor route was the only one before, which made every chip dead for them. |
| D-033 | `main` takes only squash merges from a PR, with linear history required and the commit built from the PR title + body | slice 0008 | One slice must stay one commit or `git log main` stops being the list of slices and `git revert slice-NNNN` stops reverting a whole one; taking the body from the PR keeps the build commits out of it. |
| D-034 | The Symbols call graph is derived from source at generation time, never authored in `LOGIC.md` | slice 0009 | A `uses` column goes stale within a slice, and the board's own rule is that weight is measured, not asserted. |
| D-035 | Call resolution follows unmapped local helpers transitively within a file, and stops at any name `LOGIC.md` maps | slice 0009 | The map lists deep modules and omits private helpers, so a mapped symbol's own declaration usually holds none of its real calls — `flushQueue` only delegates to `flushQueueInner`. Traversing *through* a mapped name would instead charge its callees to every ancestor. |
| D-036 | Tree expands each symbol once at its shallowest position and stubs every other occurrence | slice 0009 | The graph is a DAG: unfolding every occurrence is 217 nodes for 49 symbols, and a view of the map whose row count does not match the map is not a view of the map. |
| D-037 | Board tooling is tested by `npm run test:board` (Python `unittest`), gated in CI beside `npm test` | slice 0009 | The generator is Python and the suite is Vitest; a derived graph is the one part of the board that can be silently wrong, and porting one function to TS to reach the runner would split the tool across two languages. |
| D-038 | Tree rests closed at its entry points; opening a symbol reveals its own sentence and its children, each closed in turn | slice 0009 | An always-open tree is a longer flat list with indentation — it shows the structure without letting anyone walk it. The fold carries its child count, as the flow cases do, so a closed row still says how much is behind it. |
| D-039 | A shut tree row carries its name and its area only; the whole row is the toggle, and a chevron on the right marks it — solid when children sit under it, hollow when opening reveals just that row's own detail | slice 0009 | Narrows D-038, which had the fold carry its child count in the manner of rule 11: four things on a shut row read as a list rather than a tree, and the count it carried is on the row anyway as `N callers` once open. Solid-versus-hollow keeps the parent/leaf distinction the count was really providing, in shape rather than text, and the row-sized target means the affordance does not have to be the hit area. |
| D-040 | The board is generated, never committed: `docs/slicer.html` is gitignored, built by `npm run board` locally and by CI for Pages | tooling | A tracked render of `docs/state/` produced nothing but rebase conflicts and boards that were stale the moment a state file moved on. Nothing can now publish a copy nobody regenerated. |
| D-041 | `npm run audit` is a merge gate, with findings fatal and notes informational | tooling | The audit existed for a slice and a half without ever running, so the drift it was written to catch accumulated anyway. Splitting the output keeps it gateable: an archive naming a since-removed symbol is history, a `LOGIC.md` row pointing at a moved file is a lie. |
| D-042 | Flows are evidenced by their `.webm` clip, not by a per-flow test panel | tooling | Coverage was read from tests naming `F-` ids and no test ever named one, so the panel never rendered. The capture run already asserts what a flow test would — console clean, state surviving a reload — and fails loudly when it does not. |
| D-043 | A slice opens exactly one PR; `npm run audit` reports a slice that landed as more than one commit on `main` | tooling | Squash-only enforces one commit per pull request, not per slice — slice 0009 landed as three. Nothing can enforce it at merge time, so the rule is stated as a rule and the violation is at least visible afterwards. |
| D-044 | `/code-review`'s result is written into the archive's `### Review` block, and the audit requires the block from slice 0010 on | tooling | The process required the review and recorded it nowhere, which is the argument the Edge paths block already won: an unwritten review is indistinguishable from a skipped one. |
| D-045 | The board generator is split — `state_files.py` parses, `sourcemap.py` attributes, `callgraph.py` derives, `generate-slicer-board.py` renders | tooling | The parts with a right answer were reachable only through a 2794-line render pass, which is the god-file the quality bar forbids in app code. The render is byte-identical across the split. |
| D-046 | `npm run check` is the single gate list; CI runs exactly it | tooling | The four gates were enumerated in AGENTS.md, SKILL.md and ci.yml, three lists that drift apart the moment one gains a fifth. |
| D-047 | `NEXT.md` is reset to a no-slice-picked stub at close | tooling | It otherwise describes a closed slice until the next pick, and the board's *This slice* page presented finished work as work in flight. |
| D-048 | `/code-review` is this repo's own copy and reviews on three axes: `AGENTS.md` invariants, `NEXT.md` as the spec, the quality bar as the standard | tooling | The vendored generic skill hunted for a GitHub issue or a PRD and found neither, so the Spec axis reported "no spec available" every slice while the spec sat in `NEXT.md`. Invariants get their own axis because a reviewer reading for style reads straight past a float holding money. |
| D-049 | The board's renderer is pinned by a golden-file test over a fixture repo, markup only | tooling | Parsers and attribution were tested; the 2000-line render pass that turns their answers into a page was not. Stripping the inline CSS and script keeps a colour tweak from rewriting the fixture. |
| D-050 | `serve-slicer-board.py` binds to localhost and gates `/open` with a per-run token | tooling | The endpoint runs an editor on any path in the repo, and it was bound to `0.0.0.0` so that a Windows-side browser could reach the WSL port. WSL forwards localhost anyway; `--lan` stays for the cases it does not. |
| D-051 | The slice in flight leaves the board: `npm run delta` reports it in the terminal, and CI posts it on the PR from `merge-base...HEAD`. The board's page 04 becomes *Latest slice* — the last closed one, cut to headline, captures and the two deltas | tooling | The in-flight page rendered from the author's uncommitted working tree, so only the author ever saw it and the published board never could. A PR is per-slice (D-043), is where review happens, needs no clone, and measures what landed rather than what is dirty. The board goes back to describing the system as it stands; the archive keeps the plan, review, edge paths and decisions. Superseded in part by D-055: the PR gets a real slice page, not a markdown comment, and the published board drops the Latest slice tab too. |
| D-052 | Merging to `main` is the only way the server moves: CI pushes migrations, redeploys all five Edge Functions stamped with the merge sha, and fails unless every function reports that sha at `?health=1`. No hand deploy, no `workflow_dispatch` | slice 0010 | Hand deploy left the remote missing `expenses` and serving a stale `fetch-entity` for three slices after the archives said otherwise; a silent no-op deploy looked healthy. |
| D-053 | CI authenticates `db push` via the Supabase access token's short-lived login role; `SUPABASE_DB_PASSWORD` is not a required secret | slice 0010 | The database password is never returned by the API after creation, so requiring it would make the first green deploy depend on a human paste; the CLI already mints a login role from the token. |
| D-054 | On Realtime `SUBSCRIBED` after `CHANNEL_ERROR` / `TIMED_OUT` / `CLOSED`, run the same `syncGroup` as open for that group; no cursor | slice 0011 | A socket that dies while the hub stays open never hits D-009's open/foreground triggers; the full missed-wake protocol (a wake log) stays parked |
| D-055 | The current slice is its own slicer page, generated per PR (`--slice-page`), not a tab on the published board. CI hosts it from the `pr-boards` branch and comments the URL. The published board is Overview / Symbols / Flows / Steering only | tooling | D-051 took the in-flight slice off the board but substituted a markdown comment, so a PR still had no slicer frontend. A still of Latest slice was the same gap in a PNG. The page a reviewer needs is the board chrome with only this slice in it — in flight from `NEXT.md` + the branch diff, or closed from the archive the branch added. |
