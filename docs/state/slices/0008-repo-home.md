# Slice 0008 — repo home + published board

**Tier** — foundation-risk · **Closed** — 2026-08-07 · **Tag** — `slice-0008`

## What shipped

The project has a public home, the process travels with the clone, the gates are enforced instead of remembered, and both the board and the app are URLs. No app behaviour changed.

## Report

### Headline
The app can now be worked on by someone who is not this machine — and looked at by someone who is not this person.

### Highlights
- **The loop is in the repo.** `.claude/skills/{slicer,tdd,code-review,prototype}` are vendored, and `AGENTS.md` is a real entry point: what the app is, the slice loop, the commands, and the invariants that are not negotiable (integer cents, version-not-timestamp, soft-delete, allocations inside the expense).
- **The gates are enforced.** CI runs `npm test` + `npm run typecheck` on every PR; `main` takes squash merges only, requires linear history and a PR, and builds the commit from the PR title and body — so one slice stays one commit without anyone remembering to make it so.
- **The board publishes itself.** CI regenerates it from `docs/state/` rather than serving the committed HTML, so a stale generated file can never become the published truth.
- **The app publishes itself too**, at `/app` on the same Pages site, linked from the board's topbar. One site, no second account, no deploy token beyond the `EXPO_PUBLIC_` values the client ships anyway.
- **Path chips became real links.** They pointed at `cursor://`, which meant every one of them was dead for anyone without this clone. They now go to `blob/main/<path>#L<line>`, and the editor route survives as the localhost-only behaviour it always should have been.

### Edge paths

| Surface | State | What happens |
| --- | --- | --- |
| Path chip | published board, reader with no clone | Goes to GitHub in a new tab. This was the whole bug: chips only spoke `cursor://`. |
| Path chip | board served from `localhost` | Intercepted; the helper runs `cursor -r -g`. `data-editor` carries the URI for when the helper is absent. |
| Reference popover | published board | Missed in the first pass — built its own link from the editor URI, so one link stayed dead after every chip had moved. Fixed to follow the same rule. |
| Web export | `experiments.baseUrl` for the subpath | Export-only; the dev server still serves at the root, so `npm run capture` is unaffected. Verified before shipping, because a broken capture stays invisible until the next demo gate. |
| Published app | reload on `/app/group/<id>` | Pages has no rewrite rule, so the app's shell is served as `404.html` and the router reads the path. |
| Published app | anon key in the bundle | Baked in, as `EXPO_PUBLIC_` means. Fine only because RLS is deny-all and tokens are revocable server-side. |
| Pages build | board regenerated in CI | A stale committed `docs/slicer.html` can never be published. |
| Squash merge | branch with many WIP commits | Message comes from the PR title + body; `COMMIT_MESSAGES` was the default and would have pasted the build log into the slice's commit. |
| Secret scan | before first push | `.env` ignored, no keys in tree or history — checked before the repo went public, not after. |

## Questions asked and answered

- **Vercel or GitHub Pages for the app?** → Pages. No second account, no deploy token, one workflow, same-origin link from the board. The trade is no per-PR preview URL, which is parked.
- **PR per slice, or keep committing to `main`?** → PR per slice. The slicer skill's own exception calls for it once a repo has a remote and CI, and it makes the gate enforceable rather than remembered.
- **Public or private?** → Public. Pages on a personal account needs it, and nothing sensitive is in the tree or the history.

## Notes

**This slice was built before it was written down.** The work happened as loose chore commits answering questions in conversation, and was collapsed into one slice afterwards, with this archive and `NEXT.md` written to match what shipped. That is backwards — the gate exists so scope is agreed before code — and it is recorded here rather than tidied away, because the history was rewritten to make `main` read one commit per slice and the rewrite would otherwise hide it.

**The published board's `data-editor` attributes carry CI's runner paths.** They are inert off localhost and meaningless to a reader; the local board is what uses them.
