# Slice 0008 — repo home + published board

**Tier** — foundation-risk (nothing about the app; everything about whether the app can be worked on)

## Goal

The project lived on one machine, and the process lived in that machine's `~/.claude`. Give it a public home where the loop travels with the clone, the gates are enforced rather than remembered, and the board and the app are URLs instead of local script runs.

## Before → After

| | Now | After |
| --- | --- | --- |
| Home | Local git on `master`, no remote | `github.com/santistebanc/splitnext-app`, public, `main` |
| Process | `~/.claude/skills/slicer` on one machine | Vendored at `.claude/skills/{slicer,tdd,code-review,prototype}`; `AGENTS.md` is a real entry point |
| Gates | Run by hand at close | CI runs `npm test` + `npm run typecheck` on every PR and push |
| `main` | Convention: one commit per slice | Enforced: squash-only, linear history, PR required, commit built from PR title + body |
| Board | `python3 …/serve-slicer-board.py` on localhost | Regenerated by CI and published to Pages on every merge |
| App | `npm run web` on localhost | Static export published at `/app` on the same Pages site |
| Code links | Chips opened Cursor, so they were dead for anyone else | Chips point at `blob/main/<path>#L<line>`; the editor route is localhost-only |

## Plan

1. Vendor the skills into `.claude/skills/`; rewrite `AGENTS.md` as the agent entry point (invariants, commands, the loop); add a README.
2. Switch the slicer skill to PR per slice, since the repo now has a remote and CI.
3. `ci.yml` — tests + typecheck on PR and on push to `main`.
4. `pages.yml` — regenerate the board from `docs/state/`, export the web app, publish both.
5. Point the board at GitHub for code and at `/app` for the running app.
6. Enforce the merge rules on the branch rather than trusting them.

## Seams under test

| Seam | Behavior |
| --- | --- |
| `ci.yml` | The two gates run on every PR; a red suite blocks the merge |
| `pages.yml` | The published board is generated from `docs/state/`, never from the committed HTML |
| `repo_url` — `docs/scripts/generate-slicer-board.py` | Every chip resolves to a real file on `main`, with its declaration line |

## Acceptance

- A clone with no machine-local skill install can run the loop from `AGENTS.md`.
- A PR cannot merge red, cannot merge as a merge commit, and lands as exactly one commit.
- https://santistebanc.github.io/splitnext-app/ shows the current board; its chips open the code on GitHub.
- https://santistebanc.github.io/splitnext-app/app/ boots the app with a clean console.

## Edge paths

| Surface | State | What happens |
| --- | --- | --- |
| Path chip | published board, reader with no clone | Goes to `blob/main/<path>#L<line>` in a new tab. This was the whole bug: the chips only spoke `cursor://`, so every one of them was dead for anyone but the author. |
| Path chip | board served from `localhost` | Click is intercepted and the helper runs `cursor -r -g`; the `cursor://` URI rides along as `data-editor` for when the helper is absent. |
| Reference popover | published board | Missed in the first pass — it built its own link from the editor URI, so one link stayed on the dead scheme after every chip had moved. Fixed to follow the same rule. |
| Web export | `experiments.baseUrl` set for the subpath | Export-only. The dev server still serves at the root, so `npm run capture` is unaffected — verified before shipping, because a broken capture would have been invisible until the next demo gate. |
| Published app | reload on `/app/group/<id>` | Pages has no rewrite rule, so the app's own shell is served as `404.html` and the router takes the path from the URL. Group ids are per-device, so this path only ever means "my own group". |
| Published app | anon key in the bundle | Baked in, as `EXPO_PUBLIC_` means. Acceptable only because RLS is deny-all and every capability token is revocable server-side; a wider credential would need a server between them. |
| Pages build | board regenerated in CI, not copied | A stale committed `docs/slicer.html` can never become the published one. |
| Squash merge | branch with many WIP commits | Commit message comes from the PR title + body, so the build log does not become the slice's message. `COMMIT_MESSAGES` was the default and would have. |
| Secret scan | before first push | `.env` ignored, no keys in tree or history — checked before the repo was public, not after. |

## Out of scope

- Per-PR preview deployments (parked: **Preview deploys per PR**)
- Browser-driven flow tests in CI — capture drives real deployed Edge Functions, so it cannot be a required check
- Any change to app behaviour: this slice ships no feature
