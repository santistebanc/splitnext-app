Privacy

SplitNext has no user accounts, no email sign-in, and no passwords. Access to a group is a per-device capability token. The app records shared costs and suggests who should pay whom. It never moves money.

What we store

On a device that uses the app: group names, member display names, expenses as integer cents, how each cost is split, activity events, and the capability tokens that prove access. On a phone those tokens sit in the OS secret store; in a browser they sit in local storage.

On our Cloudflare Worker: the same group records live in a Durable Object for that group. A D1 index holds hashes of access tokens and invite secrets (not the secrets themselves), plus which device and member they belong to. Invite links are one-use and expire after seven days.

If you allow notifications on a native build, that device may register an Expo push token with the Worker so we can send a ping when someone else changes the group. We do not run ads or behavioural analytics.

The public website (this landing, the invite page, and the web app export) is hosted on GitHub Pages.

What we do not store

No login identity, no payment details, no contacts list. Member names are labels you type, not accounts. Balances and suggested transfers are derived from expenses; they are not stored as their own records.

Deletion

Leaving a group from this device revokes that device’s token and unbinds it. The member slot and expenses stay for the rest of the group. Soft-deleted rows stay in storage; they are hidden, not erased.

To ask us to delete group data we hold, open an issue on the SplitNext GitHub repository and name the group if you can. We do not verify a deletion request with a join code. There is no self-serve wipe in the app.
